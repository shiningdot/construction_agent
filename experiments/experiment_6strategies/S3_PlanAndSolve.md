# S3: Plan-and-Solve 策略

## 对标 Liu et al. (ESWA 2025)

Plan-and-Solve

## 核心思路

让 LLM **先自主制定分析计划，再按计划逐步执行**。与 S4 形成对比：S3 模型自定分解策略，S4 人工设计分解（逐层关键词检查）。

## 完整提示词

### System Prompt

```
你是施工安全事故分析专家。从事故文本中提取致因编码。

CAICS框架 (5层19类):
M管理: M1现场监管缺失 M2隐患排查失效 M3安全培训不足 M4制度规程漏洞 M5市场行为违规
F防线: F1临边洞口防护缺失 F2支撑体系失稳 F3设备安全装置失效 F4个体防护未使用
T触发: T1设备机具故障 T2物料状态异常 T3地质环境突变 T4气象水文触发
H行为: H1违反操作规程 H2违规指挥决策 H3风险辨识失败 H4应急行为失当
C后果: C1救援响应迟缓 C2信息迟报瞒报

输出最终JSON: {"codes":["M1","F2"], "accident_type":"坍塌", "severity":"较大事故", "deaths":N, "injuries":N, "direct_cause":"..."}

Let's first make a plan to analyze the accident causes, then solve it step by step.
先制定分析计划，再按计划逐步提取编码。
```

### User Message

```
请为以下事故制定分析计划并执行：

{[accident text]}
```

## 设计特点

| 维度 | 说明 |
|------|------|
| 推理过程 | **自主规划** —— 模型自己决定怎么拆解任务 |
| 示例 | 0 个 |
| API 调用 | 1 次 |
| Prompt 长度 | ~300 字 |
| 领域知识注入 | 仅 CAICS 分类名 + 输出格式 |

## 关键机制

Wang et al. (2023) 提出的 Plan-and-Solve 策略：先让 LLM 制定计划（plan），再按计划解决子任务（solve）。这个策略的关键优势是避免了 auto-CoT 中可能出现的推理步骤缺失或错误。

## 与 S4 的对照价值

```
S3: 让模型自己决定怎么拆解      → "我打算先找管理缺陷，再找物理防护问题..."
S4: 人工设计好拆解方式           → 5层关键词检查清单
```

如果 S3 ≈ S4：说明模型自主规划能力足以替代人工领域知识设计。
如果 S4 > S3：证明领域知识注入对模型推理有显著增益。
这是本实验的核心消融对比之一。
