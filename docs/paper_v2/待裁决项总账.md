# 论文侧待裁决项总账（`修订对账记录.md` 全量待决的汇总与到期核验）

> **性质**：这是一份**人读的账本**，与 `scripts/check_paper_pending_ledger.py` 成对使用。
> **它不是** `修订对账记录.md` 的替代品——原文照旧在那边，本文件只做三件事：
> ①把散落在 18 个小节里的待决条目**汇总成一张表**；②给每条**标一个状态**；
> ③给能自动复核的条目**配一个探针**，让"这句话今天还算不算数"变成机器能回答的问题。
>
> **建立日期**：2026-10-07。**源文件**：`docs/paper_v2/修订对账记录.md`（正文未改动一个字）。

## 一、为什么需要这份账本

`修订对账记录.md` 从 §6 起，每写一轮核验就在末尾留一段「待处置 / 待作者确认 / 待决（须作者裁决）」。
这些条目**读起来像待办**，但它们**是自然语言**：没有标识符、没有编号规则、没有状态字段。
写下那一刻是真的，**之后不会自我更新**——被引的节结清了、被指的文件归档了、前提其实早就变了，
而条款自己一字未动。

这与 web 侧 §2.5.97 在 `docs/web/01_在线采集.md` 上建的 `scripts/check_2597_pending_ledger.py`
是**同一个病**，只是落在论文侧。本账本照该节的方法论建：

- **标记一律不逐字写进正文**——写了会被自己的判据扫成新条目（§2.5.96 立的规矩：引述一律描述、不复述）；
- **源不可达必须判红**，不得降级成「探针返回 False」（§2.5.67）——那样「源没了」与「前提真的不成立了」在输出上一模一样；
- **登记不等于永久豁免**——每条登记都由探针**双向**核（§2.5.67）。

## 二、四态模型与两种判决

按「**这条待决的原始出发点今天是否仍然成立**」把 46 条分四态：

| 状态 | 含义 | 是否配探针 |
|---|---|---|
| `open` | **真待裁决**：前提仍在（东西还没做/文件还没建），需要作者或后续动作 | ✅ 必须配 |
| `done` | **已兑现但未销账**：原文声称"尚未做"，而实测**已经做了** | ✅ 必须配 |
| `decide` | **纯作者裁决**：不是"做没做"的问题，是"选哪个"——没有客观事实可探 | ❌ 不许配 |
| `note` | **结论性观察 / 判据边界**：不是待办，是一条需要留档的事实说明 | ❌ 不许配 |

判决只有**两种会红**：

| 判决 | 触发 | 含义 |
|---|---|---|
| `STALE-CLOSED` 🔴 | `open` + 探针 False | 原文说"还没做"，实测**已经不成立了** ⇒ 该销账 |
| `STALE-REOPENED` 🔴 | `done` + 探针 True | 原文标"已处置"，实测**又回去了** ⇒ 该重开 |
| `open-confirmed` / `done-confirmed` / `no-probe` | 其余 | 绿 |

**两种红的方向相反、互为反例**：只查一种的话，`open` 那侧"忘了销账"与"前提变了"分不开。

**6 组里 5 组状态一致、1 组相反**。这不是巧合：状态一致的那几组多是"同一次核验里顺手重写"，
而那 1 组的两处写在**相隔十一个小节**的两轮里，中间隔了一次归档动作——
**销账发生在后一处没读到的位置**。这正是本账本存在的理由。

## 六、这份账本管不到什么（判据边界）

- **基线绿 ≠ 论文可以投了**。账本只保证「待决不会被忘掉、兑现了会被发现」，
  **不保证它们被做**——`decide` 那 15 条最终要作者选，探针一句也帮不上。
- **分不出「作出声明」与「逐字引述声明」**（§2.5.96 立、§2.5.97 复立的规矩）。
  本文件与脚本里凡是提到待决内容的句子，一律用**描述**而非逐字复述——复述会被自己的切分器扫成新条目。
- **只覆盖 `修订对账记录.md`**。CLAUDE.md 的「当前待办」、`10_待执行清单.md`、
  `11_执行状态快照` 里的待决**不在射程内**；web 侧另有 `check_2597_pending_ledger.py` 管。
- **切分依赖标题结构**：小节标题必须含「待」或「作者」才会被收进扫描面。
  将来若新增一节叫「未决事项」，脚本会**看不见它**——`M4` 的节数判据会报红提示"该数变了"，
  但报的是"总数不符"而不是"你漏了 §X"，仍需人去看。
- **`open` 的探针只核「原始前提还在不在」**，不核「这件事该不该现在做」。
- **`note` 条目不判红**：它们不会被过期机制保护——将来若某条 `note` 的前提变了
  （比如 PDF 侧补上了失败路径），账本**不会**自动发现，得靠人把该条升格为 `done` 并补探针。
