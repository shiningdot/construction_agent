# 08 · 旧理论封存清单

> 状态：2026-10-01 实测。对应任务 #34（备份封存旧理论资产）。

## 一、处置结论：封存 ≠ 删除文件

用户要求是"只保留最新的 schema 表和致因分析理论，旧版本备份后封存起来"。

实测下来，**物理移走这些文件不可行**：`construction_agent/versions/`（v1 / v2 / v2_5 /
v3 / v4）与 `construction_agent/evaluation/` 是论文消融实验的基线与变体，它们
import 了 `hfacs`、`claude_extractor`、`dataset_manager`。把旧模块挪走，消融实验
立刻跑不起来——那正是 CLAUDE.md 里说的"实验对照物"，与生产链路要分开对待。

所以这里封存的是**一个状态，不是一个目录**：

> 生产链路（用户真会走到的地方）**不加载**任何一个旧理论模块，且有测试守着。

已经做到的（三道防线，逐条可复核）：

| 防线 | 位置 | 做什么 |
|---|---|---|
| ① 入口拦截 | `main.py:_LEGACY_COMMANDS` | 5 条旧命令默认拦下、退出码 2，提示里给出新命令 |
| ② 惰性导出 | 五个包的 `__init__.py`（collector / extraction / database / models / output） | `from construction_agent.extraction import ExtractionPipeline` 仍可用，但**不主动加载** |
| ③ 隔离测试 | `tests/test_legacy_isolation.py` | 子进程里跑 7 条生产入口，断言 7 个旧模块一个都不在 `sys.modules`；另测 5 条惰性导出两头都对；外加一条"幽灵检查"防止名单失真（见下） |

- `evaluation/evaluator.py`、`metrics.py`、`hfacs_evaluator.py` —— 实验框架

  `dataset_manager` 之间的互引

- `tests/test_legacy_isolation.py` 自身

**生产链路对旧模块的引用，全部是注释，不是 import**——已逐个核实：

| 文件 | 出现位置 | 性质 |
|---|---|---|
| `extraction/caics_pipeline.py:10,233` | 对照表与踩坑记录 | 注释 |

## 四、怎么一次性复核

```bash
cd /home/suntianhao/construction_agent/.claude/worktrees/classifier-mod
# worktree 下没有 .venv，解释器用主仓库那份
PY=/home/suntianhao/construction_agent/.venv/bin/python3

# ① 隔离测试（子进程里跑，判据是运行时的 sys.modules）
$PY -m pytest tests/test_legacy_isolation.py -q

# ② 入口拦截
$PY -m pytest tests/test_cli_entrypoint.py -q

# ③ 人工确认：生产命令的旧模块导入应为空
$PY -c "
import ast
src = open('construction_agent/main.py', encoding='utf-8').read()
for n in ast.parse(src).body:
    if isinstance(n, ast.FunctionDef) and n.name.startswith('cmd_'):
        hits = [a.name for s in ast.walk(n)
                if isinstance(s, (ast.Import, ast.ImportFrom)) for a in s.names
                if any(k in (getattr(s,'module','') or '') + a.name
                       for k in ('claude_extractor','dataset_manager','csv_formatter',
                                 'json_formatter','hfacs','sqlite_repository'))]
        print(f'{n.name:20s} {hits or \"无\"}')
"
```

判据为什么必须是运行时的 `sys.modules`：静态地看 import 分不清三种写法，而结论
全看是哪一种——

```python
from .claude_extractor import ExtractionPipeline   # 模块级 —— 会执行
from .claude_extractor import ExtractionPipeline   # if TYPE_CHECKING —— 不执行
importlib.import_module("...claude_extractor")     # PEP 562 —— 取了才执行
```

AST 依赖图会把 `if TYPE_CHECKING` 块里的 import 也算成真实加载边（改完惰性后图
纹丝不动，差点得出"没生效"的错误结论）。细节见 `tests/test_legacy_isolation.py`
的 docstring。
