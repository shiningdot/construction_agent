## 四、各阶段验收标准

### M0 · 基座

1. 库路径解析优先级：环境变量 `CAIEMS_DB` > `settings.DATABASE_URL` > `settings.DATA_DIR/"caiems_v2.db"`
2. 只读连接用 `sqlite3.connect(f"file:{path}?mode=ro", uri=True)` + `PRAGMA query_only=ON`
3. **写操作走只读连接必须抛异常**（用测试验证）
4. 工作库 `caiems_staging.db` 建表成功，`PRAGMA foreign_keys` 在写连接上为 ON
5. 工作库与最终库**物理分离**（两个文件），展示层代码无法访问工作库的写连接

### M1 · 展示（蓝图 04/05/06 的验收合并）

**必过项**（数据口径逐项对账）：

| 项 | 期望值 |
|---|---:|
| 事故总数 | 2,623 |
| 死亡总数 / 受伤总数 | 5,894 / 5,796 |
| 有死亡记录 / 有受伤记录 | 2,280 / 1,227 |
| 致因编码总数（行数口径） | 16,323 |
| 事故×类别覆盖数（去重口径） | 15,985 |
| 有编码的事故数 | 2,618 |
| 证据三级 | 14,784 / 1,117 / 422 |
| CAICS 五层 | M 7,077 / H 4,723 / F 2,799 / T 1,533 / C 191 |
| 共现 Top 1 | H1 + M1 = 1,821（去重口径） |
| 无编码事故 | 5 |
| 图片文件数 / 覆盖事故数 | 226 / 193 |

**功能项**：
- 全部页面返回 200，**无 500**
- 旧 web 的 17 个端点复跑，2 个 500 与 23 个空返回全部转正常
- 列表筛选下推到 SQL，`EXPLAIN QUERY PLAN` 显示走索引
- 构造 `title`/`date`/`province` 为 NULL 的记录，页面正常显示占位符

### M2 · 采集（蓝图 01 验收）

- **24 个源**在 `collect_sources` 表中一一对应
- 起一个 `limit=20` 任务能在 5 min 内完成，`raw_accidents` 新增 ≤20 条
- 任务进度落库，**重启 web 服务后不丢**
- 重复 URL 被 `UNIQUE(url_hash)` 拦截
- **产出只落库，不散在文件系统**（`data/<源名>/` 目录不再产生）

### M3 · 提取（蓝图 02 验收）

- 10 条走完 S1→S2→S3→S4，`staging_accidents` 字段**列名与最终库 `accidents` 一致**
- `evidence_quality` 与原 6 处脚本输出**逐条一致**（回归验证）
- 任务中断后已完成条目不丢、可续跑且不重复
- 四类非事故文本（`regulatory`/`aggregate`/`training`/`other`）不产生 `staging_accidents` 行
- 成本预估与实际偏差 < 30%；`actual_tokens_*` 与 `response.usage` 对得上
- 未确认的任务不产生 LLM 调用

### M4 · 审核（蓝图 03 验收）

- `dry_run` 不产生任何写操作（前后最终库文件哈希不变）
- 完整并入 10 条后：
  - `accidents` 恰好 +10 行
  - **孤儿检查为 0**：`SELECT COUNT(*) FROM caics_causes WHERE accident_id NOT IN (SELECT id FROM accidents)` = 0
- **重复并入同一批**：第二次并入后行数不变（幂等）
- 中途失败整体回滚
- 并入前自动备份存在；无参的 `POST /api/review/rollback` 能撤销最近一次并入

### M5 · 端到端串联

**一条数据的完整走查**（这是全项目的对齐判据）：

```
① 采集      在 /collect 起任务抓 1 条 → raw_accidents 新增 1 行，status='new'
② 审核闸门  自动 S1/S2 判定 → gate_verdict 写入
③ 人工确认  在 /collect 标为相关 → status='gated'
④ 送提取    在 /extract 建任务 → S1→S2→S3→S4 → staging_accidents + staging_causes
⑤ 人工审核  在 /review 打开 → 通过 → review_status='approved'
⑥ 并入      dry_run → promote → accidents + caics_causes 各新增行
⑦ 展示      在 /accidents 列表与详情页看到这条新数据
⑧ 致因分析  在 /causes 的统计中计入这条
```

**验收**：走查完成后，`accidents` 与 `caics_causes` 的总数各 +1 与 +N，且**第 ⑦ 步看到的字段值与第 ④ 步暂存的一致**（无信息丢失、无字段错位）。之后可调无参的 `POST /api/review/rollback` 撤销，恢复到走查前状态。
