# S0: Zero-Shot 策略

## 对标 Liu et al. (ESWA 2025)

Basic Zero-Shot

## 核心思路

不给任何帮助，直接让 LLM 从事故文本中提取 CAICS 编码。

## 完整提示词

### System Prompt

```
你是施工安全事故分析专家。从事故文本中提取致因编码。

CAICS框架 (5层19类):
M管理: M1现场监管缺失 M2隐患排查失效 M3安全培训不足 M4制度规程漏洞 M5市场行为违规
F防线: F1临边洞口防护缺失 F2支撑体系失稳 F3设备安全装置失效 F4个体防护未使用
T触发: T1设备机具故障 T2物料状态异常 T3地质环境突变 T4气象水文触发
H行为: H1违反操作规程 H2违规指挥决策 H3风险辨识失败 H4应急行为失当
C后果: C1救援响应迟缓 C2信息迟报瞒报

输出最终JSON: {"codes":["M1","F2"], "accident_type":"坍塌", "severity":"较大事故", "deaths":N, "injuries":N, "direct_cause":"..."}
```

### User Message

```
请为以下事故提取CAICS编码：

{[accident text]}
```

## 设计特点

| 维度 | 说明 |
|------|------|
| 推理过程 | 无 —— 直接输出 JSON |
| 示例 | 0 个 |
| API 调用 | 1 次 |
| Prompt 长度 | ~200 字 |
| 领域知识注入 | CAICS 分类名 + 每类操作定义 + 典型关键词 |

## 完整提示词

### System Prompt

```
你是施工安全事故分析专家。从事故文本中提取致因编码。

CAICS框架 (5层19类) — 每类含操作定义和典型关键词:

M.管理根基:
  M1现场监管缺失: 监理/安全员未在事故发生前发现并制止不安全状态
     关键词: 无人监管、监理失职、安全管理混乱、未及时发现制止
  M2隐患排查失效: 执行层面未能识别已存在的危险源，或未在规定时间内整改关闭
     关键词: 未排查、未整改、隐患长期存在、未进行风险评估、检查走过场
  M3安全培训不足: 作业人员未接受与岗位风险匹配的安全培训
     关键词: 未经培训、安全交底不到位、交底走过场、缺乏安全知识
  M4制度规程漏洞: 安全管理制度、施工方案、应急预案缺失或不完备
     关键词: 无安全方案、应急预案缺失、制度不健全、无施工方案
  M5市场行为违规: 违法分包/转包/挂靠/无资质/违规压缩工期
     关键词: 违法分包、无资质、转包、抢工期、未办理报建

[... all 19 categories with definitions ...]

输出最终JSON: {"codes":["M1","F2"], "accident_type":"坍塌", "severity":"较大事故", "deaths":N, "injuries":N, "direct_cause":"..."}

## 预期行为

LLM 必须仅凭分类框架的**名称**来推断每个编码的含义。作为最简基线，S0 的性能为所有更复杂策略提供了底限参照。

## 与参考论文的区别

Liu et al. 的 Zero-Shot 包含 HFACS 定义文本。本实验的 S0 同样包含 CAICS 分类名，但不提供额外解释。
