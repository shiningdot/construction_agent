# S2: Auto-CoT 策略

## 对标 Liu et al. (ESWA 2025)

Auto-CoT（"let us think step by step" 的因果链版本）

## 核心思路

要求 LLM 按因果链（M→F→T→H→C）**先写推理过程，再输出 JSON**。通过显式要求推理文字激发 LLM 的 chain-of-thought 能力。

## 完整提示词

### System Prompt

```
你是施工安全事故分析专家。从事故文本中提取致因编码。

CAICS框架 (5层19类):
M管理: M1现场监管缺失 M2隐患排查失效 M3安全培训不足 M4制度规程漏洞 M5市场行为违规
F防线: F1临边洞口防护缺失 F2支撑体系失稳 F3设备安全装置失效 F4个体防护未使用
T触发: T1设备机具故障 T2物料状态异常 T3地质环境突变 T4气象水文触发
H行为: H1违反操作规程 H2违规指挥决策 H3风险辨识失败 H4应急行为失当
C后果: C1救援响应迟缓 C2信息迟报瞒报

请按以下因果链逐步推理：M(管理缺陷)→F(防线失效)→T(触发条件)→H(人的行为)→C(后果放大)。
对每一层：判断文本中是否有相关证据，有则列出编码，无则说明"该层无编码"。
输出格式：先写一段逐层推理文字，最后单独一行输出最终JSON。JSON放在最后。
```

### User Message

```
请按M→F→T→H→C因果链分析以下事故：

{[accident text]}
```

## 预期输出格式

```
M(管理缺陷): 文本提到"安全管理混乱"→M1、"未进行安全培训"→M3
F(防线失效): 文本提到"脚手架失稳"→F2
T(触发条件): 文本提到"钢丝绳断裂"→T1
H(人的行为): 文本提到"未经检验合格即投入使用"→H1(违章操作)、"强令工人作业"→H2(违规指挥)
C(后果放大): 无相关证据

{"codes":["M1","M3","F2","T1","H1","H2"],"accident_type":"起重伤害","severity":"较大事故","deaths":3,"injuries":2,"direct_cause":"钢丝绳断裂导致升降机坠落"}
```

## 设计特点

| 维度 | 说明 |
|------|------|
| 推理过程 | **显式** —— 要求输出逐层推理文字，再输出 JSON |
| 示例 | 0 个 |
| API 调用 | 1 次 |
| Prompt 长度 | ~300 字 |
| 领域知识注入 | 因果链方向 (M→F→T→H→C)，但无具体关键词引导 |

## 关键机制

与 Liu et al. 的 Auto-CoT 一致：通过"let's think step by step"指令激发 LLM 将复杂任务分解为子步骤。区别在于，S2 将"step by step"替换为施工事故特定的因果链（M→F→T→H→C），比通用的 CoT 指令更贴合领域任务。

## 与 S4 的关键区别

| | S2 AutoCoT | S4 CAICSCoT |
|------|------|------|
| 推理指导 | 模型自定 | 每层有具体关键词清单 |
| 领域知识 | 仅因果链方向 | 每类编码配 5-6 个关键词 |
| Prompt 长度 | ~300 字 | ~1500 字 |
| 对标 | Auto-CoT | HFACS-CoT |
