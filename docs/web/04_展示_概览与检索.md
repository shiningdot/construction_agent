## 一、功能目标与用户场景

### 目标
让研究者**不写一行 SQL** 就能回答一类问题：「某地区近五年高处坠落事故的致因分布是什么」。

### 三条用户路径

| 路径 | 动作 | 系统行为 |
|---|---|---|
| **摸底** | 打开首页 | 一屏看完语料全貌：规模、伤亡、类型/等级/年代/来源构成 |
| **定位** | 设筛选条件 → 翻页 | 服务端 SQL 筛选分页，返回命中集合 |
| **深入** | 点某行 | 跳详情页（蓝图 05） |

### 设计约束
概览页必须在**没有任何点击**的情况下说清"这份数据是什么、有多大、缺口在哪"。项目历史上有过多个口径不一致（JSON 41 字段 / DB 48 列 / tool schema 30 属性 / docstring 23），**本页是口径的对外唯一出口**，数字须与 `修订对账记录.md` 一致。

## 二、数据来源

### 2.1 概览统计（全部为 SQL 聚合，不取全量记录）

| 展示项 | 实测值 | SQL 来源 |
|---|---:|---|
| 事故总数 | **2,623** | `SELECT COUNT(*) FROM accidents` |
| 死亡总数 | **5,894** | `SELECT SUM(deaths) FROM accidents` |
| 受伤总数 | **5,796** | `SELECT SUM(injuries) FROM accidents` |
| 致因编码总数 | **16,323** | `SELECT COUNT(*) FROM caics_causes` |
| 覆盖事故数 | **2,618**（5 条无编码） | `SELECT COUNT(DISTINCT accident_id) FROM caics_causes` |
| 证据等级分布 | **14,784 / 1,117 / 422** | `GROUP BY evidence_quality` |
| 年代跨度 | 1978–2026（35 个年份，1991–2004 断档） | `GROUP BY substr(date,1,4)` |
| 来源构成 | 网络 1,728（65.9%）+ 文献 895（34.1%） | `GROUP BY source_name` |

> **口径澄清（2026-09-30 实测修正）**：`deaths` / `injuries` **无空值**——两列均 `NOT NULL DEFAULT 0`，填充率 **100%**。实测 0 值的含义是「原文未提及伤亡」（S3 的 prompt 规则为「未提及填0，不编造」），而非数据缺失。因此：
>
> - `SUM(deaths)=5,894` / `SUM(injuries)=5,796` 是**全部 2,623 条的完整总和**，无需「基于有记录的 N 条」这类限定
> - 但**确有死亡记录**的事故只有 **2,280** 条（86.9%）、**确有受伤记录**的 **1,227** 条（46.8%）、两者至少其一非零的 **2,474** 条（94.3%）
> - 页面标注应写成「2,623 条中 2,280 条有死亡记录」，**不能**暗示其余 343 条是数据缺失

### 2.4 `province` 的处理（79 个取值）

**不能直接 `SELECT DISTINCT province` 当筛选选项**。实测分布：

| 组 | 数量 | 处置 |
|---|---:|---|
| 标准省级单位 | 31 个（主体，四川 191 / 浙江 161 / 黑龙江 156 …） | 正常列出 |
| 空值 | 14 条 | 归入「未标注」 |
| 境外 / 港澳台 | 26 个取值 / **45 条**（印度 11 · 香港 4+2+1 · 韩国 2 · 美国 2 · 西班牙 2 · 海地 2 …）**全部来自 safehoo** | 归入「境外及港澳台」，单独计数 |
| 地址级脏值 | ~20 条（`辽宁省沈阳市皇姑区昆山西路77-32号腾鹰科技数字产业大厦6楼605室` 等） | 归入「未归一」 |

**筛选器呈现**：省份下拉分三个分组——`内地省份`（31 个标准值）/ `境外及港澳台` / `未归一与空值`。概览页把后两组的条数**显式写出来，不并入总数**。

> 这正是 CLAUDE.md 所记"约 17 条地址级错误"的实测全貌：地址级脏值约 20 条，加上境外的 45 条与空值 14 条，异常记录合计约 60 条（2.3%）。**显性呈现而非掩盖**——这些数字本身是论文"数据质量"章节的素材。

## 三、接口设计

### `GET /api/overview`

概览页全部统计一次返回，避免多次往返。

```json
{
  "ok": true,
  "data": {
    "totals": { "accidents": 2623, "deaths": 5894, "injuries": 5796,
                "deaths_recorded": 2280, "injuries_recorded": 1227,
                "casualty_any": 2474,
                "causes": 16323, "causes_covered": 2618 },
    "evidence_quality": [ {"key":"direct_quote","label":"直接引用","count":14784},
                          {"key":"indirect_infer","label":"间接推断","count":1117},
                          {"key":"weak_infer","label":"弱推断","count":422} ],
    "severity":  [ {"key":"一般事故","count":1889}, ... , {"key":null,"count":1} ],
    "accident_type": [ {"key":"坍塌","count":1092}, ... ],
    "year":      [ {"key":"1978","count":12}, ... ],
    "source":    [ {"key":"safehoo","count":1247,"track":"network"}, ... ],
    "caics_layer":[ {"key":"M","label":"管理","count":7077}, ... ],
    "province_group": { "standard": 31, "overseas": 45, "unnormalized": 20, "empty": 14 }
  }
}
```

**`deaths_recorded` / `injuries_recorded` / `casualty_any` 必须返回**——语义是「**有**伤亡记录的事故条数」（`deaths > 0` 等），不是「非空」。见第 2.1 节的口径澄清。

### `GET /api/accidents`

| 参数 | 类型 | 说明 |
|---|---|---|
| `q` | string | 关键词，匹配 `title` + `summary` + `direct_cause` |
| `province` | string | 标准省级值；或特殊值 `__overseas__` / `__unnormalized__` / `__empty__` |
| `severity` | string | 四值之一 |
| `accident_type` | string | 13 种之一 |
| `project_type` | string | 9 种之一 |
| `construction_phase` | string | 9 种之一 |
| `year_from` / `year_to` | int | 年份区间 |
| `has_causes` | bool | 只看已编码 / 未编码 |
| `sort` | string | `date`（默认降序）· `deaths` · `title` |
| `page` / `size` | int | 默认 1 / 50，上限 200 |

**响应**：

```json
{ "ok": true,
  "meta": { "total": 2623, "page": 1, "size": 50, "pages": 53 },
  "data": [
    { "id":"5cd6ec7f8873", "date":"2026-06-16", "title":"…",
      "accident_type":"坍塌", "severity":"较大事故",
      "deaths":3, "injuries":1, "province":"陕西省", "city":"西安市",
      "work_task_label":"起重设备安拆与吊装", "cause_count":9 }
  ] }
```

> `province` 在列表中同时给出原值与归一后的显示标签。`work_task_label` 由服务端查 `enum_definitions` 得到中文名，**前端不硬编码编码表**。

### SQL 生成要点

```sql
SELECT a.id, a.date, a.title, a.accident_type, a.severity,
       a.deaths, a.injuries, a.province, a.city, a.work_task_enum, a.work_task,
       (SELECT COUNT(*) FROM caics_causes c WHERE c.accident_id = a.id) AS cause_count
FROM accidents a
WHERE 1=1
  /* 动态拼接，全部用参数占位符，禁止字符串插值 */
  AND a.province = ?                      -- 标准值走精确匹配
  AND a.severity = ?
  AND a.accident_type = ?
  AND substr(a.date,1,4) BETWEEN ? AND ?
  AND (a.title LIKE ? OR a.summary LIKE ? OR a.direct_cause LIKE ?)
ORDER BY a.date DESC
LIMIT ? OFFSET ?
```

**必须配 `COUNT(*)` 独立查询**取 total（不要 `SELECT` 全量再在 Python 里数）。

`__overseas__` 等特殊值展开为 `a.province IN (...)` 的子句，境外清单由服务端内置的常量集合提供。

## 四、页面结构与交互逻辑

### 4.1 布局

```
┌─ 顶栏（base.html：导航 + 主题切换）────────────────┐
├─ ① 口径条 ────────────────────────────────────┤
│  2,623 条事故 · 5,894 人死亡 · 16,323 条致因编码   │
│  覆盖 1978–2026 · 网络 65.9% + 文献 34.1%        │
│  ⚠ 1991–2004 无记录 · 1991–2004 采集缺口说明      │
├─ ② 五张分布图（严重程度/类型/年代/来源/致因层级）──┤
├─ ③ 筛选条 ────────────────────────────────────┤
│  [关键词] [省份▾] [等级▾] [类型▾] [工程类型▾]      │
│  [工序▾] [年份区间] [仅看已编码☐] [重置]           │
├─ ④ 结果摘要：命中 128 条 · 第 1/3 页 ────────────┤
├─ ⑤ 列表表格（9 列，服务端分页）─────────────────┤
└─ ⑥ 分页控件 ───────────────────────────────────┘
```

### 4.2 交互逻辑

**服务端筛选（与旧版的关键差别）**

旧版 `dataset.html` 把全部记录塞进页面，筛选靠前端 `JSON.stringify(r).includes(q)` 遍历，且**首屏有 3 处 None 崩溃点**（`:372` title、`:374` severity、`:381` location）——而其 JS 重渲染路径反而有 `|| ''` 兜底，于是出现"首屏 500、但一点筛选就正常"的诡异行为。

新版：
- 筛选条**任何变化都触发 `GET /api/accidents`**（含 300 ms 防抖），不再全量下发
- 列表由 **JS 渲染**（表格 9 列结构固定，服务端只给数据），避免 Jinja 与 JS 两套渲染逻辑并存
- 每次响应携带 `meta.total`，结果摘要与分页控件据此更新
- **URL 同步**：筛选状态写入 `location.hash`（如 `#province=浙江省&severity=较大事故&page=2`），便于分享与回退

**空值兜底**：服务端出口统一把 `null` 保留为 `null`，前端渲染一律 `v ?? '—'`。**不再出现"某条记录某字段为空就整页崩"的情况。**

**列头排序**：日期 / 死亡数 / 标题三列可点，切换 `sort` 参数并重查。

## 五、技术选型与理由

| 选择 | 理由 |
|---|---|
| **服务端筛选分页** | 2,623 条虽可全量下发，但详情页的编码与证据链不可；统一走 API 才能复用同一套查询层。旧版 `/api/dataset` 一次吐 21.5 MB 是反例 |
| **JS 渲染列表 + Jinja 只出壳** | 避免旧版"两套渲染逻辑行为不一致"的坑。首屏数据由 `GET /api/overview` + `GET /api/accidents` 拉取 |
| **图表用 CSS 横条 / 内联 SVG** | 旧 `causes.html` 的 `.level-bar` / `.cat-bar` 已证明可行；**不引 CDN**，保证离线。若需环形图（严重程度），用内联 SVG 弧线 |
| **`enum_definitions` 查表出中文名** | 编码含义只在库里存一份，前端不维护副本 |
| **省份三分组用内置常量** | 34 个省级单位是稳定知识，写进后端常量模块（复用 `utils/location.py:14-61` 已有的 34 个省级单位清单与 `:77` 的 70 条别名映射） |

**可复用的现成资产**：`construction_agent/utils/location.py` 已有 34 个省级单位、70 条别名、151 条城市→省份映射——**省份归一与分组直接复用它，不重写**。

## 七、验收标准

1. `GET /api/overview` 的 `totals` 与直接 SQL 查询逐项一致；`evidence_quality` 三项为 **14,784 / 1,117 / 422**
2. `GET /api/accidents` 无参数时返回 2,623 条中的前 50 条，`meta.total = 2623`、`meta.pages = 53`
3. 各筛选参数单独与组合生效，结果条数与 `SELECT COUNT(*)` 的等价查询一致
4. `q=塔吊` 命中数正确；含空格/中文/特殊字符不报错（全程参数化查询）
5. `province=__overseas__` 命中 **45** 条；`__unnormalized__` 命中约 **20** 条；三分组计数之和 + 标准值计数 = 2,623
6. `has_causes=false` 命中 **5** 条
7. 页码越界（`page=9999`）返回空列表而非报错
8. 响应时间：无筛选列表页 < 300 ms（索引生效后）
9. 首屏无 500；**构造 `date` 为 NULL / `province` 为 NULL / `title` 为 NULL 的记录，页面正常显示占位符**

## 八、已知风险与待决项

| # | 项 | 说明 | 建议 |
|---|---|---|---|
| **A** | **`work_task` vs `work_task_enum`** | 实测：两列都非空且**不同**的有 **1,392** 条；**仅 `work_task` 有值**的 664 条；两列都空 421 条；仅 `work_task_enum` 有值 0 条 → `work_task_enum` 只填充了 1,538 条，**枚举 v2.0 迁移未完成**（`pipeline_metadata` 记录迁移日期 2026-07-28）。同一条记录可能出现 `work_task=WT06`（起重设备安拆与吊装）而 `work_task_enum=WT08`（桥梁工程）的矛盾 | **取 `work_task_enum` 优先、为空回退 `work_task`**；在「关于数据」页显式说明该列 1,085 条缺失；**列为独立的数据修复任务**，不在 web 范围内解决 |
