**怎么读「列表」栏**：它是「这个源在列表页上一共列了多少篇」，与「收到了几条」
是两件事——后者被早停钉死在 `--limit`。看到一页量级（≤25）时会挂提示。
第七轮给这条提示判了性质——**它两头都不准**：四个待查源全部落在提示区间内，
查完却都是正确全量（**误报**）；而 `beijing_em`(84) / `hebei_em`(110) 这类**一页就
超过 25 条**的站，提示根本不响（**漏报**）。能定音的只有**页面自证**——站点自己
渲染的「共 N 页」「最后一页」，或列表接口返回的 `count` 字段；这条提示的作用
退化为「指出值得再看一眼的地方」（01 §2.5.8）。

**怎么读「闭环」栏**（第八轮新增）：核的是 `列表 == 收录 + 审核 + 排除`。
**四个取值里只有两个是结论**，另两个是「不适用」——混着数会得出「十几个源
闭环失败」这种自己吓自己的结论：

| 取值 | 含义 |
|---|---|
| `✓` / `差 N` | 跑到底的真实对账结果——**结论**。`差 N` 意味着有条目进了循环却没落到任何去向 |
| `早停` | 列表超过 60 条，探针没跑到底——不适用 |
| `空表` | 列表解析出 0 条，`0 == 0 + 0 + 0` 恒真——不适用 |
| `—` | 6 个源没记这几个计数器——不适用 |

**「条数」栏带 `*` 的** = 被早停截断，等于 `--limit`，**不是抓到了这么多**；
不带的 = 列表本就短、跑到底的真实候选数。两者不要横向比。

**「结果」栏的 `空` 与 `没连上`** 也是第八轮拆开的：站点通了但栏目确实没内容，
与 DNS 挂了 / TLS 谈不成 / 被 412 拦，此前在表上逐格相同。后者现在单独成一档
（`jl_em` DNS、`jx_em` SSL 老式重协商、`hub_em` 412 反爬）。**只覆盖 12 个 TRS 源**，
其余源（如 `esafety` 未配置 Token）仍只有 `空` 一种。

#### 可达面：这些写路由谁能到达（§2.5.93）

```bash
.venv/bin/python3 scripts/check_2593_reachability.py --self-test    # 18 组正反用例，纯文本，秒级
.venv/bin/python3 scripts/check_2593_reachability.py --inject-test # 4 例：I1 关 Host 层 / I2 关守卫

```

**这一节问的是上一节的下一句**：§2.5.92 问「**要删的东西，问过谁**」，这一节问「**谁能把请求
送到这些路由**」。要紧的不是"再查一层有没有登录"，而是**第二问会反过来改写第一问的效力**：
§2.5.92 把 `promote` 的服务端一次性令牌封为 L2 样板，而**凭证只在「攻击者拿不到既有状态」时
才是防线**——一旦有人能**读到**本机接口，`promote_id` 就从只读接口里取得出来、L2 随即失效。

**三层可达性，一层一层往下**：

| 层 | 实测 | 结论 |
|---|---|---|
| **绑定面** | `FLASK_HOST` 默认 `127.0.0.1`、`.env` 未覆盖、`FLASK_DEBUG` 默认关 | **对的**，不用改 |
| **身份面** | `web/` 下 9 个鉴权别名**全部零命中**；`FLASK_SECRET_KEY` 只在 `config.py` 声明、`factory.py` 赋值，web 里**一次 session 都没用过** | **零身份面**，它是**死配置** |
| **浏览器面** | 同源策略拦的是「**读**」不是「**发**」 | **「本机」≠「只有你」** |

**13 条写路由按「能不能被一个跨源 `<form>` 打到」分三档**（判据纯静态：`method` ×
「实现读不读 body 的键」，**不真打**——真打要真改库，§2.5.86 划的禁区）：

| 档 | 条数 | 路由 |
|---|---|---|
| **表单可达** | **4** | `POST /api/collect/tasks/<id>/cancel`、`POST /api/extract/tasks/<id>/cancel`、`POST /api/extract/tasks/<id>/start`、`POST /api/extract/results/<id>/rerun` |
| 需预检 | 7 | 读 JSON body ⇒ 跨源要预检，而全站**零 `Access-Control-*` 头** |
| 表单发不出 | 2 | 两条 `DELETE`（HTML `<form>` 发不出这些方法） |

那 **4 条与 §2.5.92 的 L0/L1 判定完全重合**——两条判据在同一条路上各走了一半，**重合处才是
真风险面**：既打得到、又没问过。三档之和 == 13 是**元判据当场断言**。

**真缺口是 DNS rebinding**：`TRUSTED_HOSTS` / `SERVER_NAME` 都没设 ⇒ **伪造 Host 照常 200**
（连 `127.0.0.1.evil.com` 这种后缀伪装都放行）。攻击链：诱导访问 `evil.com` → 把该域名 A 记录
改成 `127.0.0.1`（TTL=0）→ 浏览器认为攻击页与 `127.0.0.1` **同源** ⇒ 不但能发、还能**读**响应
⇒ `promote_id` 读得出来 ⇒ **§2.5.92 的 L2 在它面前不构成防线**。原先挡着的两道门**全是设计
意外的副产品**：①JSON content-type ⇒ 预检 ⇒ 零 CORS 头 ⇒ 读 body 的写路由打不到；
②`POST` 是 CORS 安全方法 ⇒ 跨源表单**不触发预检、不需读响应** ⇒ 输入全在 URL 里的 POST 能直打。

**⚠ 本节改了生产代码**（`construction_agent/web/factory.py`，两处）：

```python
TRUSTED_HOSTS = ["127.0.0.1", "localhost", "[::1]"]        # ①Host 层
UNSAFE_METHODS = frozenset({"POST", "PUT", "PATCH", "DELETE"})

@app.before_request                                        # ②Origin 同源守卫
def _same_origin_guard(): ...   # 非安全方法 + Origin 存在且不一致 ⇒ 403
```

**两条互为依赖**：只留 `Origin` 校验，攻击者可用 rebinding 把 Host 伪装成 `127.0.0.1` 从而
「同源」；只留 `TRUSTED_HOSTS`，跨源表单写照样打到那 4 条不需要 body 的路由。

**⚠ 坑一：`app.config.setdefault("TRUSTED_HOSTS", …)` 是空操作**——Flask 的 `default_config`
里**本来就有这个键**（值 `None`），`setdefault` 见 key 已存在就不覆盖 ⇒ **那一层整层不存在**，
而**不报错、不抛异常、配置读出来也不崩溃**（首版实测四个伪造 Host 全 200）。终版改成判
**「调用方有没有显式传」**。这是 §2.5.64「退出码 0 只有当脚本有能力报 1 时才可信」的同一副面孔。

**四格实测**：同源写**穿过**（400，业务层拒）／跨源写 **403 被守卫拦下**／不带 `Origin`（`curl`）
**穿过**／跨源 **GET 不受影响**；Host 面真 Host 全放行、伪造 Host 全 **400**；叠加场景 **400**。

**⚠ 五条边界**：①`Origin` 守卫挡的是**「浏览器被利用」不是「本机以外的客户端」**（不带 `Origin`
的一律放行，那一格是**明写这件事**、不是漏测）；②`Origin` 那条**依赖 `TRUSTED_HOSTS`**（同源
判定取自 `Host` 头）；③本节**不核「这些路由该不该需要鉴权」**（产品决策）；④E 段是**静态分类
不是真打**；⑤**改 `FLASK_HOST` 部署形态、或改 `factory.py`，本节全部结论作废**。

**⚠ 连带复跑**：改的是**每个请求都过的 `before_request`** ⇒ 须复跑全部起服务的核验脚本
（`check_2580`–`2587`、`check_2592`、`check_web_interaction.py`、`check_web_alignment.py`、
`check_field_alignment.py`、e2e 系列、截图）。
