**怎么读「列表」栏**：它是「这个源在列表页上一共列了多少篇」，与「收到了几条」
是两件事——后者被早停钉死在 `--limit`。看到一页量级（≤25）时会挂提示。
第七轮给这条提示判了性质——**它两头都不准**：四个待查源全部落在提示区间内，
查完却都是正确全量（**误报**）；而 `beijing_em`(84) / `hebei_em`(110) 这类**一页就
超过 25 条**的站，提示根本不响（**漏报**）。能定音的只有**页面自证**——站点自己
渲染的「共 N 页」「最后一页」，或列表接口返回的 `count` 字段；这条提示的作用
退化为「指出值得再看一眼的地方」（01 §2.5.8）。

**怎么读「闭环」栏**（第八轮新增）：核的是 `列表 == 收录 + 审核 + 排除`。
**四个取值里只有两个是结论**，另两个是「不适用」——混着数会得出「十几个源
闭环失败」这种自己吓自己的结论：

| 取值 | 含义 |
|---|---|
| `✓` / `差 N` | 跑到底的真实对账结果——**结论**。`差 N` 意味着有条目进了循环却没落到任何去向 |
| `早停` | 列表超过 60 条，探针没跑到底——不适用 |
| `空表` | 列表解析出 0 条，`0 == 0 + 0 + 0` 恒真——不适用 |
| `—` | 6 个源没记这几个计数器——不适用 |

**「条数」栏带 `*` 的** = 被早停截断，等于 `--limit`，**不是抓到了这么多**；
不带的 = 列表本就短、跑到底的真实候选数。两者不要横向比。

**「结果」栏的 `空` 与 `没连上`** 也是第八轮拆开的：站点通了但栏目确实没内容，
与 DNS 挂了 / TLS 谈不成 / 被 412 拦，此前在表上逐格相同。后者现在单独成一档
