## 二、实测证据（可逐条复核）

### 2.1 `local_path` 是相对 `data/` 的路径

样例：`images/12de680adf6c/23693d248c0d.png`

    $ ls -la data/images/12de680adf6c/

    $ file data/images/12de680adf6c/23693d248c0d.png
    PNG image data, 640 x 426, 8-bit/color RGBA, non-interlaced

### 2.2 全量核验（1,037 条逐条 stat，不抽样）

| 指标 | 值 |
|---|---|
| 登记总数 | 1,037 |
| **文件存在** | **1,037（100%）** |
| 大小为 0 | 0 |
| 魔数不像图片 | 3 |
| **不存在** | **0** |
| 唯一文件路径 | 830（其余 207 行为重复引用同一文件） |
| 文件大小 | 最小 8,338 B ／ 中位 45,584 B ／ 最大 14,606,245 B |

### 2.3 对照：两个口径的命中率

| 口径 | 命中 | 说明 |

蓝图 06 的「404」结论只对第二行成立，而第二行**不是** `local_path` 的语义。

## 三、错因

三版图片目录是**迭代产物**（`images/` → `imageV2/` → `imageV3/`），蓝图
把「以最终版 `imageV3/` 为唯一真源」当成了正确目标，于是：

1. 只检查 `imageV3/` 内部一致性（登记 211 vs 磁盘 226 vs 目录 427）；
2. 发现对不上，得出「三版混存，替换规则没法统一」；
3. 由此推断「按 `local_path` 取图会 404」——**跳过了"另外 826 条指向的目录也在磁盘上"这一步验证**。

「最终版」是**采集策略**上的概念（最新一轮爬取结果），不等于「唯一有效的图片」。
旧版目录里的图片**一直躺在磁盘上、也一直在数据库里登记着**。

## 四、影响

### 4.1 web 丢掉 80% 的图片

`web/images.py:27` `MEDIA_ROOT_DIRNAME = "imageV3"`，`web/views.py:83` 的
`/media` 路由同样只认 `imageV3/`。重建的 `image_manifest` 扫的也是
`imageV3/`（`scripts/build_image_manifest.py`）。后果：

| 指标 | 只服务 imageV3 | 三版合并 |
|---|---|---|
| 覆盖事故数 | 176 | **476** |
| 可展示图片 | 226 | **817** |
| 有图事故中**完全没图**的 | — | **300 个（63%）** |

### 4.2 「覆盖率」统计被低估 2.4 倍

`web/images.py:166` 把覆盖率注释为「采集完整性的真实反映」：

> 覆盖率只有 7.4%（193/2,623）。这个数字**必须显式呈现**——它是采集
> 完整性的真实反映，藏起来才像缺陷。

但 193 是 `image_manifest`（只含 `imageV3`）的事故数。三版合并是 **476**，
即 **18.1%**。**这个数字当前不是"采集完整性"的反映，而是截断的产物**——
比注释担心的"藏起来像缺陷"更糟：它把一个偏高的事实显示成了偏低。

### 4.3 去重的理由与实际代价不成比例

`web/images.py:25` 的原始顾虑：

> 只服务最终版。`images/` 与 `imageV2/` 不给——三版里同一事故可能有重复
> 图片，放出来读者没法判断哪张是最终采用的。

实测重复规模：

| 项 | 数量 |
|---|---|
| 同时在 ≥2 个版本有图的事故 | 57 / 476（12%） |
| **跨版本同名文件（真重复）** | **13 张** |
| 因截断丢失的唯一图 | **558 张** |

为规避 13 张重复而丢掉 558 张唯一图，**代价是收益的 43 倍**。

而且这个顾虑**有更直接的解法**：保留三版并**显式标注来源版本**，读者就能
自己判断哪张是最终采用的——比隐藏更符合「让数据说话」。

## 五、修复方案

原则：**不改最终库**（论文数据），只改展示层的取材范围与标注。

1. **`scripts/build_image_manifest.py`**：扫描范围从 `imageV3/` 扩到
   `images/` + `imageV2/` + `imageV3/` 三版；每条记录增加 `version` 字段
   （取 `rel_path` 的第一段）。
2. **`web/images.py`**：`MEDIA_ROOT_DIRNAME` 改为允许的版本白名单
   `{"images", "imageV2", "imageV3"}`；`rel_path` 校验由「必须以 `imageV3/`
   开头」改为「第一段在白名单内」，`realpath` 落在 `data/` 之内。
3. **`web/views.py:83`** 的 `/media` 路由同步放开。
4. **展示层**：图片条目显示版本角标（`最终版` / `历史版本`），重复图片
   （同 `sha1`）按事故内去重时**保留最高版本**。
5. **覆盖率口径**：`accidents_with_images` 改用合并口径，并在文案里说明
   其中多少来自历史版本。
6. **更正蓝图**：本文即为 `06` 的更正；`06` 顶部加指向本文的提示。
