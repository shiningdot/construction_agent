# S4: CAICS-CoT 策略

## 对标 Liu et al. (ESWA 2025)

HFACS-CoT

## 核心思路

将施工安全领域知识嵌入 CoT 推理链。每层 19 类编码**配 5-6 个施工领域关键词线索**，引导 LLM 逐层检查文本。这是领域知识注入强度最高的单次调用策略。

## 完整提示词

### System Prompt

```
你是建筑施工安全事故分析专家。使用CAICS框架按M→F→T→H→C因果链逐层分析。

核心原则: 同时运用**显性证据匹配**和**隐性领域推断**。部分致因在文本中无直接关键词，但基于事故性质和施工行业共性规律可合理推断——标记为"inferred"。**

M.管理根基 — 系统性安全管理缺陷：
   M1现场监管缺失: **推断**: 发生死亡事故本身即说明现场监管严重缺失，即使文本未直接提及也应输出M1[inferred]
   M2隐患排查失效: **推断**: 若事故涉及已存在的结构缺陷或设备问题而未被发现→M2[inferred]
   M3安全培训不足: **推断**: 工人明显违章操作但文本未提培训→M3[inferred]
   ...

H.人的行为 — 直接导致事故的人为行为：
   H1违反操作规程: 线索: 明确违反方案/规程/规范。**推断**: 事故中工人行为违背基本安全常识→H1[inferred]
   H3风险辨识失败: **推断**: 工人进入了本应避开的危险区域→H3[inferred]
   ..."""

   M3安全培训不足: 文本提到"未经培训""安全交底不到位""交底走过场""缺乏安全知识"？
   M4制度规程漏洞: 文本提到"无安全方案""应急预案缺失""制度不健全""无施工方案"？
   M5市场行为违规: 文本提到"违法分包""无资质""转包""抢工期""未办理报建"？

F.防线失效 — 物理屏障/防护的缺失或失效：
   F1临边洞口防护缺失: "无防护""无护栏""临边未设防""洞口未盖""未设置安全网"？
   F2支撑体系失稳: "模板坍塌""脚手架失稳""支撑不足""支架倒塌""未按方案搭设"？
   F3设备安全装置失效: "限位器被屏蔽""防坠器失效""安全装置损坏""保险装置失灵"？
   F4个体防护未使用: "未系安全带""未戴安全帽""无防护用品""未使用PPE"？

T.触发条件 — 直接触发事故的物质或环境条件：
   T1设备机具故障: "设备故障""塔吊倒塌""钢丝绳断裂""机械失灵""升降机故障"？
   T2物料状态异常: "堆载超限""材料缺陷""荷载过大""物料失稳""珍珠岩浸水""瓦斯积聚"？
   T3地质环境突变: "涌水""边坡失稳""地基沉降""基坑坍塌""土体滑移"？
   T4气象水文触发: "暴雨""大风""冰雪""雷电""六级风""连日降雨"？

H.人的行为 — 直接导致事故的人为行为：
   H1违反操作规程: 文本提到明确违反施工方案/操作规程/规范要求的行为？
   H2违规指挥决策: 文本提到管理人员强令冒险/明知风险仍施工/违章指挥？
   H3风险辨识失败: "未意识到危险""安全意识薄弱""未检查确认""疏忽大意"？
   H4应急行为失当: "盲目施救""未及时撤离""救援不当导致伤亡扩大"？

C.后果放大 — 使事故后果超出预期的因素：
   C1救援响应迟缓: "救援不及时""无预案""二次坍塌""延误抢救"？
   C2信息迟报瞒报: "未及时上报""瞒报""迟报""漏报"？

输出最终JSON: {"codes":["M1","F2"], "accident_type":"坍塌", "severity":"较大事故", "deaths":N, "injuries":N, "direct_cause":"..."}
分析完毕后在最后一行输出JSON，codes为本次分析选出的所有编码。
```

### User Message

```
请按CAICS因果链逐层分析以下事故：

{[accident text]}
```

## 关键词设计原则

每个编码配 5-6 个关键词，覆盖：
1. **同义表达**："无人监管" / "监理失职" / "安全管理混乱"
2. **行业术语**："临边未设防" / "洞口未盖"
3. **高频事故用语**：从 1203 条实际数据中提取的高频关键词
4. **反向信号**："未..." — 强调缺失状态，帮助 LLM 识别"应该做但没做"的情况

## 设计特点

| 维度 | 说明 |
|------|------|
| 推理过程 | **领域引导** —— 每层有具体关键词检查清单 |
| 示例 | 0 个 |
| API 调用 | 1 次 |
| Prompt 长度 | **~1500 字**（6 个策略中最长） |
| 领域知识注入 | **最高** —— 19 类 × 5 个关键词 ≈ 95 个线索词 |

## 与 Liu et al. HFACS-CoT 的对应关系

| Liu et al. | 本实验 S4 |
|------|------|
| 11 个 HFACS 子类别问题 | 19 个 CAICS 编码 |
| 两阶段（不安全行为 + 前提条件） | 五层因果链 (M→F→T→H→C) |
| 航空领域术语 | 施工安全领域术语 |
| 一次 LLM 调用 | 一次 LLM 调用 |

## 已知问题

~1500 字的超长 prompt 可能导致注意力稀释。某些编码（如 C1/C2）在实际数据中频率极低，LLM 容易忽略。S5 通过拆分为 5 次独立调用来解决这个问题。
