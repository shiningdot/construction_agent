# S1: Few-Shot 策略

## 对标 Liu et al. (ESWA 2025)

Basic Few-Shot

## 核心思路

在 Zero-Shot 基础上加入 3 个真实事故案例，每个案例展示完整的 "文本 → 编码 + 基础信息" 映射，让 LLM 通过上下文学习理解标注粒度。

## 完整提示词

### System Prompt

```
你是施工安全事故分析专家。从事故文本中提取致因编码。

CAICS框架 (5层19类):
M管理: M1现场监管缺失 M2隐患排查失效 M3安全培训不足 M4制度规程漏洞 M5市场行为违规
F防线: F1临边洞口防护缺失 F2支撑体系失稳 F3设备安全装置失效 F4个体防护未使用
T触发: T1设备机具故障 T2物料状态异常 T3地质环境突变 T4气象水文触发
H行为: H1违反操作规程 H2违规指挥决策 H3风险辨识失败 H4应急行为失当
C后果: C1救援响应迟缓 C2信息迟报瞒报

以下3个真实案例展示了如何提取CAICS编码：

示例1(坍塌/特别重大/74死2伤):
文本:"江西丰城电厂三期工程冷却塔施工平桥吊坍塌，造成74人死亡2人受伤。工人在拆除冷凝塔外围木制脚手架时，尚未干透的混凝土开始脱落，导致整个施工平台坍塌。"
输出:{"codes":["M1","M2","F2","T2","H1"],"accident_type":"坍塌","severity":"特别重大事故","deaths":74,"injuries":2,"direct_cause":"拆除脚手架时混凝土未干透导致平台整体坍塌"}

示例2(起重伤害/重大/12死):
文本:"福建霞浦县一建筑工地发生载人升降机坠落事故，造成12人死亡。升降机未经检验合格即投入使用，施工单位安全管理混乱，未对作业人员进行安全培训。"
输出:{"codes":["M1","M3","M4","F2","T1","H1","H2"],"accident_type":"起重伤害","severity":"重大事故","deaths":12,"injuries":0,"direct_cause":"升降机钢丝绳断裂且未经检验合格投入使用"}

示例3(高处坠落/重大/10死2伤):
文本:"西安市凯玄大厦工地发生附着式升降脚手架坠落事故，造成10人死亡2人受伤。事故发生时脚手架从20层坠落，工程存在违法分包、安全监管薄弱等问题。"
输出:{"codes":["M1","M5","F2","H1","H2"],"accident_type":"高处坠落","severity":"重大事故","deaths":10,"injuries":2,"direct_cause":"附着式升降脚手架从20层坠落"}

输出最终JSON: {"codes":["M1","F2"], "accident_type":"坍塌", "severity":"较大事故", "deaths":N, "injuries":N, "direct_cause":"..."}
```

### User Message

```
请参照示例为以下事故提取CAICS编码：

{[accident text]}
```

## 示例选择

| 案例 | 类型 | 等级 | 死亡 | 编码数 | 覆盖层 |
|------|------|------|:--:|:--:|------|
| 江西丰城电厂 | 坍塌 | 特别重大 | 74 | 5 | M,F,T,H |
| 福建霞浦升降机 | 起重伤害 | 重大 | 12 | 7 | M,F,T,H |
| 西安凯玄脚手架 | 高处坠落 | 重大 | 10 | 5 | M,F,H |

3 个示例覆盖了事故类型三极（坍塌/起重/高坠）、等级两极（特别重大/重大）和 4 个 CAICS 层级（M,F,T,H）。

## 设计特点

| 维度 | 说明 |
|------|------|
| 推理过程 | 无 —— 模式匹配 |
| 示例 | 3 个真实 GT 案例 |
| API 调用 | 1 次 |
| Prompt 长度 | ~800 字 |

## 与参考论文的区别

Liu et al. 同样使用 3 个示例，从 GAHFACS 数据集中选取。本实验使用 3 个 CAIEMS 真实案例。
